# OpenGrade 技术架构(M0 内核)


## 模块职责

| 模块 | 职责 | 关键决策 |
|---|---|---|
| `auth` | 四级角色(admin/leader/teacher/student)、Argon2id 口令散列(唯一第三方依赖 x/crypto;存量 PBKDF2 散列登录自动升级)、随机令牌会话 | 会话落盘可恢复,账号持久化 data/org.json;API 层中间件按角色控权 |
| `card` | 版式模型 v2(题型化)+ 考号码制通道(`RegMode`:填涂/条码/二维码/双通道)、容量校验、mm→px 几何编译、SVG/PNG 双渲染 | 出卡/读卡/切片共用 `Sheet` 像素几何,机制性消灭"模板错位";码区几何与涂卡同源 |
| `font` | 最小 TrueType(ttf/ttc)解析 + 扫描线光栅化(2×超采样抗锯齿)+ 系统中文字体发现 | 零依赖实现中文位图;缺字体自动退化内置点阵;OMR 判读只依赖几何,与字体无关 |
| `omr` | 自适应二值化、定位角标(三级兜底:Otsu→局部自适应→墨迹百分位)、透视矫正、题型感知判读、考号逐位明细+码制解码(条码多线投票/二维码 RS 纠错,以码为准修复涂卡)、主观题切片、调试叠加图 | 纯 Go 零依赖;矫正先行,判读与物理摆放无关;码在矫正后的标准网格上解码 |
| `roster` | 学生名册(JSON/CSV)+ 考号"可读位匹配"推荐 | 异常卷自愈的规则版;唯一判读位必须精确命中,多涂位命中加分 |
| `score` | 客观对分 + 主观人工分合并(含批注笔迹)、逐题得分率、低分率题筛选 | 得分率即讲评备课数据源(方案稿『一键讲评 PPT』的底座) |
| `export` | 成绩册 xlsx/csv、讲评课件 pptx(纯 zip+xml 的 OPC 包) | 零依赖生成 Office 交付物;PPTX 用绝对定位文本框+图片,免母版依赖 |
| `synth` | 合成透视+旋转+光照+噪声的模拟扫描(带 5% 页边距) | 无扫描仪环境下的持续容错回归(CI 靶场) |
| `raster` | 像素绘图原语 + 5x7 点阵字体 + 覆盖度混合 | 零依赖;字体光栅化的底座 |
| `barcode` | Code 128 编码(107 符号码表、mod-103 校验、数字走 Code C 更紧凑)与单线解码(游程归一化自同步 + 边缘噪点剥离重试) | 零依赖;只面向矫正后正向扫描线,通用性让位于可靠性 |
| `qrcode` | QR v1~v4 数字模式:GF(256) RS 编解码(BM+Chien+Forney)、格式信息 BCH、8 掩码惩罚评分;区域解码走「已知矩形+定位图形互验」捷径 | 零依赖;考号 ≤12 位恒用 v1(模块 ~1.4mm),纠错能力留 5 处余量 |
| `cmd/ogctl` | gen/read/slice/score/demo | demo 是端到端验收入口(含异常卷自愈与全部导出产物) |
| `cmd/ogserver` | 原子 API + 考试会话存储 + 阅卷工作流 + 走班数据范围(班级集合交集语义)+ 考场编排(落盘/对调/监考)+ 导出端点 | net/http 标准库;data/ 目录 JSON 落盘,重启恢复 |
| `web/` | 设计器 + Grader Studio(键盘盲操、手写批注、增强、指派) | 零构建原生 JS |

## 关键算法

### 定位(omr/locate.go)
在二值图上以 2 倍降采样做 4-连通域 BFS,对每个连通域施加三重先验:
1. 尺寸 ≈ 5mm 定位方块在该分辨率下的期望边长(0.5×~2.0×);
2. 实心度 bbox 填充率 ≥ 0.85(实心圆仅 0.785,天然排除涂卡圆);
3. 中心落在对应象限且距期望位置 < 25% 图宽。

任一象限失败即报错并携带诊断信息(而不是静默错位)。

### 矫正(omr/homography.go)
四点对四点的 DLT 单应拟合(固定 h33=1 的 8×8 线性方程组,Gauss-Jordan 消元),
把整页重采样回 300 DPI 标准网格后重新二值化。旋转、透视、翻拍视角问题一次消除。

### 二值化(omr/bitmap.go)
- **全局 Otsu**:常规扫描(双峰直方图)首选,快且稳;
- **局部自适应(Bradley 积分图)**:每像素与邻域均值比较,对强阴影、污渍、
  翻拍光照不均稳健;CLI/API 以 `-threshold adaptive` 显式启用;
- 定位与判读使用同一模式,保证"看到什么判什么"。

### 判读(omr/omr.go)
每个涂卡圆只统计内部 0.8r 圆域的墨迹占比(避开描边):≥ 阈值(默认 0.42)判涂;
阈值下 0.12 以内记"涂写偏浅"告警。题型感知:
- choice/judge:多涂记告警并按错判处理(判断题选项字母为 T/F);
- multiple:多涂合法,原样输出由统分与参考答案精确比对;
- 考号逐位判读,任一位漏涂/多涂即置 `regValid=false` 并告警——交由上层做
  学籍名册模糊匹配(方案稿『考号智能容错重影匹配』,EE/M3)。

### 主观题切片(omr/slice.go)
矫正图按 `Sheet.SubjectiveBoxes`(共享几何,外扩 1.5mm)逐题裁剪,
输出 `Slice{StudentIndex, RegNumber, QuestionIndex, Image}`——
阅卷工作台的最小作答单元。在线路径由 ogserver 建考时自动切片并落盘。

## 开放数据格式

```jsonc
// sheet.layout.json —— 版式契约(v2 题型化;v1 文件读取时自动规范化)
{ "version": 2, "title": "高一(3)班 月考答题卡", "regDigits": 8, "columns": 2,
  "questions": [
    { "kind": "choice",   "options": 4, "score": 2 },
    { "kind": "judge",    "score": 2 },
    { "kind": "multiple", "options": 4, "score": 2 } ],
  "subjectives": [
    { "kind": "fillblank",  "score": 5,  "heightMM": 16 },
    { "kind": "subjective", "label": "解答题", "score": 10, "heightMM": 42 } ] }

// result_XX.json —— 识别结果(answers 与 questions 一一对应;judge 用 T/F,多选如 "AC")
{ "regNumber": "00000003", "regValid": true,
  "answers": ["C","C","B", "..."], "warnings": ["第 12 题 B 选项涂写偏浅,建议人工复核"] }

// report.json —— 合并统分报告(客观对分 + 主观人工分,分值加权)
{ "count": 3, "total": 80, "mean": 16.5,
  "students": [{ "index": 1, "regNumber": "00000001", "objective": 16, "subjective": 5,
                 "score": 21, "total": 80, "flagged": false }],
  "perQuestion": [{ "index": 31, "kind": "fillblank", "max": 5, "mean": 2.5, "graded": 3, "count": 3, "rate": 0.5 }] }
```

考试会话(data/exams/{id}/):`exam.json`(版式/答案/OMR 结果/评分)+ `slices/s{nn}_q{mm}.png`,
整目录拷贝即迁移。

## 已知边界(按路线图依次解决)

1. 局部自适应二值化已就绪(adaptive 模式);默认模式仍为 Otsu,真实扫描样本库继续校准;
2. 手写姓名 OCR 未实现 → 异常卷先用名册"可读位匹配"推荐 + 人工指派(已可用),OCR 属 M3;
3. 考试会话存储为目录 + JSON(已可重启恢复)→ SQLite(纯 Go 驱动)待依赖评审后迁移;
4. 讲评课件为开源基础版(规则聚合);大模型作文批改/预打分属 M4 商业企业版;
5. PPTX/XLSX 为最简 OPC 实现,已通过 XML 结构校验与主流办公软件兼容性基线,复杂样式按需增强;
6. 会话为内存态:服务重启后需重新登录(账号本身已持久化);接 SQLite 时一并持久化会话;
7. 教师数据范围:考试可见性 = 任教班级 ∧ 任教学科(或本人创建);报告/成绩册/导出按任教班级过滤(索引原位、评分键不变);阅卷不受班级过滤(跨班职责,`?grading=1`);未配置学科/班级的教师只能看本人创建的考试;
8. 双评仲裁、多校联考调度、信创集群属 M4/M5 商业企业版,社区版保持边界。

## 全系统复核测试

鉴权与四级权限矩阵(12 项越权断言)、出卡/读卡 API、建考全流程(切片 15 + 整卷 5 落盘核数)、
任务分配、阅卷与批注笔迹、异常卷推荐指派、报告与班级聚合、四种导出产物的解包深度校验
(xlsx 部件/csv BOM 与指派考号/数据包 15 切片与内嵌 report/pptx 结构)、
学生端报告与错题本计数断言、答卷回溯、隐私隔离、用户管理、
重启持久化(数据在、旧会话失效)、删除清空。任何一次改动后都应先跑它。
